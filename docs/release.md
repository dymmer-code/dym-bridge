# Releases

A tag `vX.Y.Z` builds every system and publishes the archives and `checksums.txt`.

## macOS: signing and notarization

macOS only opens an app downloaded from the internet if it is signed with a Developer ID and notarized by Apple.
When the five secrets below exist in the repository, the macOS jobs sign the app, put it in a `.dmg`, notarize the
disk image, staple the ticket and publish the `.dmg`. Without them the same styled `.dmg` is
published unsigned and the job prints a warning.

| Secret | Content |
|---|---|
| `MACOS_CERTIFICATE_P12` | the *Developer ID Application* certificate with its private key, exported as `.p12`, in base64 |
| `MACOS_CERTIFICATE_PASSWORD` | the password chosen when exporting the `.p12` |
| `MACOS_NOTARY_KEY` | the App Store Connect API key (`AuthKey_XXXX.p8`) in base64 |
| `MACOS_NOTARY_KEY_ID` | the key id of that API key |
| `MACOS_NOTARY_ISSUER_ID` | the issuer id shown in App Store Connect, Users and Access, Integrations |

The `.p12` and the key are never printed and are deleted at the end of the job.


## Branded macOS disk images

Requires Python 3.12+ (override with `make dmg-deps PYTHON=/path/to/python3` if macOS selects its system Python).

Local: `make dmg-deps && make dmg` produces `bin/dym-bridge.dmg` (arm64 + amd64, CGO_ENABLED=0). `make dmg-package` packages an existing bundle, preserving its signature. The background and Finder layout are generated by pinned dmgbuild/Pillow tools in `packaging/macos/dmg`; there is no Finder/AppleScript dependency.

CI generates the same styled DMG for each macOS architecture, even without signing secrets. With secrets, it signs the bundle, rebuilds the styled DMG, signs/notarizes/staples it. The callback scheme remains `dym-bridge` and the bundle identifier remains `com.dymmer.bridge`.
